# open-image-2-generator

SillyTavern 原生 UI 扩展：自动读取回复末尾的 `<pic prompt="...">` 并生成图片，支持按角色名与别名匹配参考图、图生图、上下文提示词整理、图片预览与日志。运行时无需 TavernHelper / JS-Slash-Runner。

## 安装与更新

将此仓库放在 `SillyTavern/data/<用户>/extensions/open-image-2-generator` 下，确保该目录直接包含 `manifest.json`，然后刷新 ST 页面。默认从输入框左侧的魔法棒（酒馆扩展菜单）里的 **image2 参考图** 打开面板，入口可以改成右下角的悬浮窗，见下文“生图入口”。

仓库发布到 Git 远端后，也可以在 ST 的“扩展 → 安装扩展”中填写仓库地址安装，并通过扩展管理更新。目前本仓库没有配置 Git 远端。

### 本机开发

本机使用目录联接，让 ST 直接加载这个工作目录：

```text
D:\programming\SillyTavern\data\default-user\extensions\open-image-2-generator
  → D:\programming\silly\open-image-2-generator
```

首次建立连接：

```powershell
./scripts/setup-local.ps1
```

其他安装位置：

```powershell
./scripts/setup-local.ps1 -SillyTavernRoot 'D:\your\SillyTavern' -UserHandle 'default-user'
```

直接编辑源码后刷新 ST 页面即可，无需打包或重新导入脚本。浏览器仍显示旧版本时，使用 Ctrl+F5 强制刷新。安装脚本遇到已有的其他目录会报错，不会覆盖该目录。

## 从旧脚本迁移

先在酒馆助手脚本库中关闭旧的 image2 脚本，再刷新 ST，避免重复生成和面板冲突。旧脚本可以保留作为备份。

扩展首次启动会读取全局脚本、当前角色脚本或当前聊天补全预设中保存的 image2 配置，并将其迁移到 ST 扩展设置。若同时存在多份配置，优先读取启用的脚本；仍有多份候选时会提示先保留一份，避免误选配置。迁移完成后，扩展独立保存设置。

参考图片继续使用原来的浏览器 IndexedDB，标题折叠状态沿用原来的 localStorage 键。使用相同的浏览器配置和 ST 地址时，这些数据可以继续使用；更换浏览器、端口或域名时，先在旧面板导出参考图库，再在新面板导入。

`open_image2_character_reference.json` 是归档的 TavernHelper 版本，后续开发编辑原生扩展源码。

## 默认配置与存储

图片服务默认地址为 `http://127.0.0.1:8199/v1/images/generations`，默认模型为 `gpt-image-2`。服务地址、模型、请求参数和提示词可在面板中修改。图片请求沿用浏览器直接访问图片服务的方式，服务需允许 ST 页面跨域访问。

提示词整理支持酒馆当前连接、ST 反向代理预设和独立 API。当前连接使用 ST 原生生成接口，覆盖模型时使用聊天补全连接；独立 API 与反向代理通过 ST 聊天补全后端发送请求。发给 AI 的 Prompt 由第 4 步选中的预设决定，见下面的「提示词预设」。

「5. 生图测试」里的聊天楼层用于定位素材，留空时取最后一条 assistant 消息。运行生图测试在提示词框为空时，先按「提取提示词正则」从该楼层取提示词，再发给图片后端；「从上下文生成提示词」把该楼层正文和截到该楼层为止的聊天历史交给第四步的 AI 整理；「从上下文中提取提示词」只按同一个正则从该楼层取提示词，不调用 AI。三个按钮都只写入面板，不改动聊天。

第四步的「世界书片段」素材条目启用时，插件用 ST 自己的世界书激活逻辑（`checkWorldInfo`，dry run 模式）对截到该楼层的聊天求激活，再按「世界书激活条目上限」截断。世界书内容和关键词命中都按选中楼层计算，但读取的是当前的全局设置、当前选中的书和当前角色书，ST 不保存每层的历史快照。

设置存储于 `extensionSettings.open_image_2_generator`，参考图片存储于 IndexedDB `oair_image2_character_reference_v1`，标题折叠状态存储于 localStorage `oair_image2_character_reference_collapsed_sections_v1`，面板拖拽位置存储于 localStorage `oair_image2_character_reference_panel_position_v1`，面板尺寸存储于 localStorage `oair_image2_character_reference_panel_size_v1`。

## 提示词预设

第 4 步的「整理预设」和「补救预设」各自从一个预设库里挑一个预设，两个选择互相独立，都只影响本插件发出的提示词整理请求。预设是一条有序 Prompt 链，每条 Prompt 可以单独开关、改名、改内容，并选择以系统 / 用户 / 助手的身份发送。

内置素材条目负责把插件读到的内容放进请求，包括本次 assistant 回复、角色卡、世界书片段、最近聊天记录和聊天变量。它们和自定义 Prompt 在同一条链上，位置、开关和角色都能调整，关掉的素材不会被读取。被关掉或读空的条目不会产生空消息。

Prompt 内容支持酒馆宏（`{{char}}`、`{{user}}`、`{{getvar::名字}}`、`{{random::甲,乙}}` 等），在发送前替换。走聊天补全时由插件替换，走文本补全时交给酒馆替换，两种路径都只替换一次。插件另外提供两个专用宏：`{{image2_context}}` 插入角色卡、世界书和最近聊天记录，`{{image2_reply}}` 插入本次 assistant 回复正文。聊天变量涉及隐私，只有显式打开「聊天变量」条目才会读取，也不会被 `{{image2_context}}` 一起带出。

「措辞控制规则」是预设里的一条普通 Prompt，可以编辑、关闭或删除。旧版本会把它强制追加到整理规则和补救规则末尾，现在不再追加，第 1 步的主模型注入规则仍然自动追加。

面板里的预设编辑器可以新建（从默认条目起步）、复制为副本、重命名、删除、恢复默认条目，也可以导出和导入。「导出全部」写出一个 `image2-prompt-profiles.json`，`type` 为 `oair-image2-prompt-profiles`；导入只认这个格式，冲突的预设 id 会重新分配，重名的预设会加 `(2)` 后缀，无效条目会被丢弃。编辑器在手机上同样可用：条目排序用上移 / 下移按钮，卡片头部和按钮行会自动换行。

从旧版本升级时，`summaryPrompt` / `fallbackPrompt` 里的内容会在首次加载时迁入「默认整理」「默认补救」预设的指令条目，末尾的措辞控制规则会被切出来交给独立的「措辞控制规则」条目；旧的「读取该楼层会激活的世界书片段」「读取聊天变量」两个开关会转成对应内置条目的开关。迁移结果会立刻落盘，之后不再重复迁移。

## 生图入口

酒馆的「扩展」设置页左侧有一栏 **image2 角色参考图**（`#extensions_settings` 里的 `inline-drawer`），里面的「生图入口」有两个互斥选项：

| 选项 | 入口位置 |
| --- | --- |
| 输入框旁边的魔法棒 | 挂到酒馆扩展菜单（`#extensionsMenu`）里的 **image2 参考图** 菜单项 |
| 可拖拽悬浮窗 | 右下角常驻的 **image2 参考图** 按钮，按住可以拖到屏幕任意位置 |

默认是魔法棒。切换后立刻生效，不需要刷新页面，也不需要点保存。两个入口都是点击切换面板的显示/隐藏，打开的是同一个面板，拖动和缩放行为完全一致。设置保存为 `entryPoint`（`wand` 或 `floating`）。

悬浮按钮拖动时按位移区分：移动超过 4px 算拖拽，松手不会误触面板开关；停下后位置写入 localStorage 键 `oair_image2_character_reference_launcher_position_v1`，刷新后保留。没拖过的按钮仍贴右下角，并按可视化视口补偿浏览器底栏和软键盘；拖过之后位置超出屏幕时会自动收回可视范围。

设置里的 **重置悬浮窗位置** 按钮会删掉这条位置记录，把按钮放回右下角初始位置。这个按钮只在悬浮窗模式下可用，选魔法棒时置灰。

## 面板布局

面板标题栏固定在窗口顶部，滚动内容时始终可见。

窗口尺寸固定，默认宽 `min(900px, 100vw - 24px)`、高 `min(780px, 100vh - 80px)`，内容在窗口内滚动，所以切换 Tab（含图库）不会改变窗口宽高。

移动端（走酒馆的 `isMobile()` 判断，或窗口宽度不超过 1000px）忽略上面的尺寸并铺满屏幕，上边界贴 `#top-bar` 底边、下边界贴底栏顶部。高度按这两条栏位实时测量后直接写成像素高度，不使用 `dvh`，也不依赖 `fixed` 元素的 `top`/`bottom` 拉伸，所以不会顶到 iPhone 状态栏，也不会被页面根元素的 `transform` 影响。自定义酒馆换了栏位 id 时，脚本按 `send-form`、`send_form`、`form_sheld` 的顺序取第一个可见元素，都没找到则退回 `env(safe-area-inset-*)`。

大屏按住标题栏可拖动窗口位置，拖动右边、下边或右下角可调整窗口大小（最小 320×240，最大不超过视口）。位置和尺寸写在上面的两个键里，超出可视范围的数值会在窗口尺寸变化时自动收进屏幕。

## 持久生成图库

所有生成结果（包括生图测试和多图返回）默认上传到 ST 当前用户的 `user/images/open-image2/`。聊天回显使用 ST 图片链接，刷新后仍可显示。原有 base64 轻量回显和临时图库副本设置不再参与生成流程。

每张图片对应一个 `user/files/open-image2-<图片ID>.json`，记录来源聊天与楼层内容、Persona 名称/描述、角色卡快照、原始和提交 Prompt、生成时间、请求耗时、保存前流程耗时、保存时累计耗时、请求次数、模型/尺寸和参考图信息。记录不包含图片 API 认证头或密钥。角色卡和聊天快照可能包含私人内容，请按聊天资料管理这些文件。

“生成图库”独立 Tab 支持 Persona、角色卡与本地生成日期范围组合筛选，筛选会显示成可单独取消的标签。缩略图按本地日期分组（今天、昨天、具体日期），图上标出参考图数量与生成耗时；点击缩略图打开大图，来源聊天、角色卡、耗时、Prompt 与完整元数据在同一层里查看，也可以用“打开原图”下载。刷新图库会重新从 ST 读取文件。生成期间切换聊天或切换来源楼层的 swipe 时，结果保存到图库并跳过聊天写回。远程图片 URL 需要允许浏览器跨域下载；下载或保存失败会在状态中显示错误。元数据保存失败时，已保存的图片路径会出现在错误消息中，图库会明确报告缺失记录。
